# ADR-0039 — Languages: Spanish, Portuguese (Brazil) and German

- Status: Accepted
- Date: 2026-10-20
- Extends: ADR-0013 (website, consent and monetization), ADR-0006 (security headers)

## Context

Picstea was English only. Much of the audience for free browser photo editors searches in other
languages. Product decisions (Sia): Spanish, Portuguese (Brazil) and German first; the website and
the editor UI together; machine-drafted translations shipped without native review (said so on
the About page and in the changelog).

## Decision

- **URLs.** English keeps every existing URL. Other languages live under `/es`, `/pt-br` and `/de`
  (`/de/png-editor`; `/de` is the editor). All routes moved under `app/[lang]`, so both root
  layouts get the language as a root param (`next/root-params`) and render `<html lang>`.
- **Proxy.** Unprefixed paths are rewritten to `/en/…` internally; `/en/…` redirects (308) to the
  unprefixed URL, so English has one address. Other languages pass only for translated pages
  (`TRANSLATED_PATHS`); everything else is a real 404. Files with an extension and `_next` are
  untouched. With Cache Components `dynamicParams` is gone, so the root layouts also call
  `notFound()` for any unknown language.
- **No automatic language redirect.** Crawlers and shared links get predictable pages. The site
  header and the editor's Help → Language menu switch languages; an explicit choice is remembered
  (`picstea.lang`) and only then does the editor at `/` move to that language.
- **SEO.** Translated pages carry `hreflang` for every language plus `x-default`; the sitemap lists
  each language version with alternates. Docs, blog and legal pages stay English: no hreflang, and
  translated pages link to them as English pages.
- **Security policy.** `SITE_ROUTES` and the CSP header rules match language prefixes, so
  `/de/png-editor` gets the website policy and the editor (`/de`) keeps the strict one.
- **Website copy.** Each translated page has `src/content/pages/<slug>/<lang>.tsx` exporting a
  `PageCopy`; routes render the copy of the route's language. Shared phrases are typed
  dictionaries (`src/i18n/site/<lang>.ts`, checked against the English shape). `LocalLink` keeps
  links in the page's language when the target is translated.
- **Editor UI.** Gettext style: the English text in the code is the key (`t("Gaussian Blur")`),
  catalogues map keys per language (`src/i18n/editor/<lang>.ts`), a missing key shows English, and
  English needs no catalogue at all. The server passes only the current language's catalogue to
  the editor (`I18nProvider`), as data, not code. Labels defined in maps are marked with `N_()`;
  registry names (filters, adjustments, tools, effects) are translated where they are shown.
- **Engine stays English and framework-free.** Messages with values are `Msg` templates
  (`msg("{label} could not be applied…", { label })`) carried by `FormatError`, `ExportError`,
  failed results and notices — also across the worker boundary; the UI translates the template and
  formats numbers in the user's language. Plain messages are looked up as they are.
- **Completeness tests.** A collector gathers every key (`t()`/`N_()` literals, registries,
  engine messages and history labels); a unit test fails when a language misses one, when a
  translation changes `{placeholders}`, or when `t()` is given a template literal.
- **No new dependency.** The runtime is about 60 lines (`translate`, `fill`, the provider).

## Consequences

- Adding a language: a code in `LOCALES`, a site dictionary, a copy file per translated page, an
  editor catalogue; the tests list what's missing.
- Every page is prerendered once per language (four times the build output for site pages).
- Document data that users create (layer names such as "Layer 1") stays as created; only the UI is
  translated.
- Translations are machine-drafted. Native review is welcome and only touches the language files.
